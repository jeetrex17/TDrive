# Agent instructions

## Pull requests

Use [the repository PR template](.github/PULL_REQUEST_TEMPLATE.md) when creating or editing a pull request body. Keep these three sections, in this order:

1. Description: explain what the change does, including meaningful scope or behavior.
2. Related Issue: use `Resolves #N` only when the PR fully resolves that issue; otherwise use `Related to #N`. Write `None` if there is no related issue.
3. Motivation and Context: explain the problem and why the change matters.

Keep the title and body short and clear. Do not add a testing section, test commands, test results, CI status, or a checklist to the PR body unless the user explicitly asks for them. Do not use em dashes. When editing a user-written body, preserve their wording where possible while applying this format.
